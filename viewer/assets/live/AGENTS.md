# Live Assistant DOX

## Purpose and ownership

- Own the persistent browser Live session controller (`controller.ts`), sidebar (`panel.ts`), runtime entry (`index.ts`), semantic OHIF adapter (`ohif.ts`), PCM input worklet/output queue (`audio*.ts`), and wire guards (`protocol.ts`).
- The backend owns actor identity, provider credentials, model configuration, ready state, tools, review requirements, session context versions, and transcript/research history. The renderer owns visible OHIF execution and media controls.

## Runtime contract

- Use the fixed protocol in `roadmap/ai-backend/LIVE_IMPLEMENTATION.md`; compile structural compatibility assertions against `@radsysx/clinical-web` in `scripts/live-contracts.ts`. Keep dynamic OHIF service access in `ohif.ts`; `series.ts` contains the focused pinned Cornerstone rendering boundary.
- Input is PCM16 little endian, mono, in 20 ms packets resampled from the actual AudioContext rate: Gemini uses 16 kHz (640 bytes) and OpenAI uses 24 kHz (960 bytes). The default worklet configuration remains 16 kHz. Output is PCM16 mono 24 kHz. Providers may generate speech faster than real time: buffer normal reply bursts at the original playback rate, with a 60-second duration bound (plus 10 ms scheduling lead) and at most 3,000 scheduled source nodes. Include the incoming chunk in both limits before allocating decoded audio or a source; an oversized first chunk must not bypass the bound. User interruption flushes all scheduled speech and pending transcript rendering immediately. Manual Stop speaking suppresses the rest of the current utterance until the interaction ends or a fresh user turn/provider interruption occurs.
- Raw microphone audio and image frames are transient only. No localStorage/IndexedDB media or transcript persistence. Durable text/tool history goes through authenticated backend endpoints. Historic conversation viewing ends an active call to prevent mixed playback.
- Provider selection is explicit and backend-allowlisted: Gemini (`gemini-3.8-live-extended-thinking`) remains default; OpenAI (`gpt-realtime-2.1-mini`) is separately selectable when configured. A session freezes provider, exact model and sample rates from its backend response. Switching provider ends the previous session, stops media, clears recovery/attestation and starts a new conversation. Recovery requires the same provider and exact model as well as the same target. Never silently switch providers after a failure.
- If provider discovery fails before the desktop login cookie is established, expose an explicit Retry assistant setup action. Retrying discovery must populate the provider choices without allocating a conversation or implying data attestation.
- The Settings affordance stays available before connecting. Use authenticated `/api/ai/sidebar/credentials` status plus PUT/DELETE per allowlisted provider. Saved keys override app environment configuration; show saved, app-configured, missing, or unreadable status without key fragments. Entry uses stable masked password fields, never prefilled or put into controller state, history, URLs, logs, analytics, or browser storage. Clear all entered values on submit, close, disconnect, context/attestation invalidation, and panel unmount. Ordinary transcript/status rendering must preserve an in-progress input. End the current session and clear attestation before any key write; the backend terminates all sessions/jobs owned by that account. Refresh the provider catalog after changes without restarting the app, and never describe saving as provider verification. Disable saving when secure storage is unavailable, but keep removal available for an unreadable saved key; explicitly disclose environment fallback before removal.
- OpenAI emits an `audio_chunk` marker before each binary output frame; discard unmarked OpenAI audio. Track sample playback by item ID/content index and send `playback_stop` with audible `audioEndMs` on interruption, manual stop or queue overflow. Prefer the Web Audio output timestamp, otherwise subtract available output latency. Never acknowledge queued bytes as heard. Gemini remains compatible with unmarked PCM and ignores playback acknowledgments.
- Require explicit synthetic/deidentified attestation; never infer it from an imported file. Only backend provider setup `ready` enables media. Microphone and image sharing each need their own user action. Permission denial keeps typed text available.
- Screen capture uses the Electron lease API with the active OHIF viewport ID and integer CSS bounds. Capture at most once per second after the last capture completes. End, logout, route/mode exit, target changes, permission failure, and socket loss stop sharing and input. Reconnection does not automatically resume media or replay actions/audio.
- After obtaining a capture lease, send transient `screen_sharing` with `active: true` before frames, and send `active: false` on stop while transport is available. `screen_status` confirms backend sharing state and receipt of the current image; show starting, waiting, image sent, and off states accurately. Ignore late positive receipts after a local stop, and stop capture without echoing when the backend turns sharing off. Never persist these receipts or infer image availability from a connected session. Label the scope as the active image viewport with a neutral modality/image number, not the whole app screen. Ending/reconnecting clears media receipts and the prior interaction label.
- After unexpected transport/provider failure, require fresh data confirmation before manual recovery. Recover only the same authenticated, unexpired, nonclosed session with the same target; obtain its server context version and reattest through `/context`. Restore bounded text/tool/citation history and seed replay guards before opening a fresh provider connection. Never resume mic/screen automatically. Explicit End or a target change starts a new conversation.
- Send only neutral structured viewer state and opaque aliases for tools. Raw study IDs are backend-only context from a resolved governed launch. Never send patient labels or DICOM metadata through tool state. Changing target invalidates attestation, shuts down media, and requires reconnect. Same-target state changes are debounced and synchronized before text turns/action receipts.
- Convert VOI ranges back to conventional window width/center using Cornerstone’s `abs(high-low)+1` and `(low+high+1)/2`, not a simple difference/midpoint.
- Renderer actions are a semantic allowlist over OHIF services/commands. Measurement geometry follows the native type-specific contracts documented below. Scoped segmentation edits operate existing attached representations; model-generated mask inference is deferred. Saves and deletion stay behind backend approval. No arbitrary JavaScript, selectors, filesystem/network tools, or direct STOW.
- Report drafting may populate a reversible local unsaved preview and a governed workspace draft. Local-only DICOM needs worklist import/association before backend saving. Never mislabel a local draft as saved.
- When Cornerstone is loaded, report drafts share `HistoryMemo.DefaultHistoryMemo` with annotations, including manual viewer edits. Undo/redo must follow the actual combined edit order; the report card says “Undo latest edit.” A bounded local draft-only history is permitted before Cornerstone is available.
- Model citations permit only HTTP(S), no embedded credentials; Search suggestions render in a CSP-restricted sandboxed iframe. Escape text and arguments in sidebar markup.
- Controller lifetime is independent of sidebar re-render/remount. It binds to OHIF managers through the extension ready event and ends the session on mode exit.

## Explicit saved-result Jev review

- `evidence.ts` owns independent prepare/start/retry/cancel and saved-result GET polling; `evidence-panel.ts` renders exact frozen claims/abstracts, exclusions, five abstract-scoped judgments and execution receipts in a dedicated review workspace reached from completed PubMed research cards. It never feeds judgments into conversation, reports or viewer actions.
- Require separate public-literature/synthetic text confirmation and a nonempty backend-issued claim selection. Image attestation is insufficient. No edited prose or browser evidence payload is accepted. Clear consent on selection/preview/session/account change and every attempted start/retry; retain an uncertain operation's key for retransmission.
- Guard every awaited response by generation, even if abort is ignored. One poll at a time, 1/2/4-second backoff, 100-second limit and explicit GET-only Refresh. End voice and collapse preserve background reviews. Session changes/unmount stop subscriptions; saved history/remount reads results without inference. Settings/account changes invalidate outstanding replies and consent.
- Keep one stable host per tool. Transcript and sibling tool updates must preserve focused selection/confirmation controls; status and receipt regions update independently. Native labels/details and escaped text keep controls accessible. Configuration appears as one Settings row; only a saved resolved-model receipt establishes completion. Never reduce NVIDIA catalog options to accommodate review UI.

- Preserve the browser fetch global receiver: a default injectable fetcher must wrap `fetch(input, init)` rather than invoke native fetch as a controller method. Node's permissive fetch is insufficient coverage; retain the receiver regression and actual Electron path.

- User preference (2026-09-22): the AI sidebar is for radiologists in a reading room. Use an understated charcoal/slate palette with muted blue accents, readable subdued text, soft borders and dark native scrollbars. Avoid bright mint/white button fills, neon glows and distracting animation. Preserve visible keyboard focus, clear states and compact conversation space. Theme only the AI surface, preserving diagnostic image rendering.

- Failed/interrupted preparation, cancelled/unavailable reviews and previews without eligible claims expose an explicit **Prepare review again** action. Create a new owned preparation without modifying prior records or making Jev calls; clear consent and require confirmation for its new preview. Reopen selects the newest saved review for that tool. Refresh remains GET-only, and uncertain preparation retransmission keeps its operation key.

- Keep Chat transcript, Research results and Jev review in separate persistent workspaces. Research cards show the question, status, formatted answer and one Jev action; source lists and execution details are collapsed. Jev review hides the composer and unrelated results, explains preparation versus actual inference, and shows only abstracts linked to selected passages. Empty previews never claim readiness. Workspace navigation does not infer or reset confirmation. Reopening, account/session/selection changes clear confirmation; GET refresh never infers. Terminal status overrides stale progress; ending voice refreshes owned receipts or shows status unconfirmed.

## Text without a voice connection

- Send uses an owned HTTP text session when voice is disconnected; Research explicitly starts a literature job without relying on a voice model to choose a tool. Both require fresh synthetic/deidentified confirmation for the case. Settings selects their standard text/research provider/model independently of voice. The disclosure states neutral metadata/question only unless the user explicitly attaches a current viewport image to a Codex request. Do not imply pixel awareness from metadata.
- HTTP jobs preserve drafts until acknowledged, reuse the operation identity after an uncertain send, bound GET-only polling, show progress/cancellation/model receipts and restore saved output. Ignore every stale response after session/context/account changes. End joins backend jobs; opening history ends the active text session. The Connect voice action explicitly starts a new voice conversation; media controls still depend on acknowledged Realtime readiness. Text sessions never open a WebSocket or prepare audio.

## ChatGPT / Codex subscription

- `presentation.ts` formats escaped paragraphs, bold spans, inline code and lists only. It never enables generated HTML, images or links. The original answer/claim bytes remain unchanged in backend evidence artifacts. In the Research composer, Enter runs research; in Chat, Enter sends text. Both retain the same unsent draft and attestation requirements.

- `subscription.ts` owns Settings login/status/sign-out and bounded GET-only polling. Keep the OAuth URL transient and validate HTTPS official hosts; never handle tokens/passwords or open model-provided destinations. Show confirmed account/plan, preserve the existing text/research model until explicit selection/save, and distinguish subscription allowance from voice API billing. Stop polling and discard stale responses after settings closure/disposal. Account changes stop owned work and clear attestation before dispatch.
- Codex models come from the authenticated backend catalog. Recorded provider/model receipts must label ChatGPT/Codex subscription; no voice/audio session is created for text. Research uses the backend PubMed dynamic tool and retains the existing explicit Jev preview/confirmation.

- **Attach current view** is a Codex Chat/Research action independent of Realtime. Fresh synthetic/deidentified confirmation starts one main-process capture lease, captures the active viewport with visible overlays, then stops the lease. Keep a removable, expandable preview only in memory; no provider receives pixels until Send/Research. Reject stale target/state/revision, expired preview or late capture replies. Uncertain sends preserve their exact image and operation key; known image-capability rejection preserves the draft and permits changing the attachment. ACK/end/account/context invalidation clears the preview. Show saved image receipts alongside chat/research results without recreating pixels. Never claim full-series review or continuous screen access.

- Shared study-exploration DTOs are re-exported from `@radsysx/clinical-web`; they keep transient image observations separate from receipts and acknowledged coverage. Runtime activation is separate from type availability.

- `series.ts` owns complete native display-set inventories, including expanded multiframe IDs, stable opaque SHA-256 handles and bounded manifest paging (256 descriptors/58 KiB page). Private image IDs stay in the renderer. Require complete known geometry and a single study; cap task inventory at 32 series/10,000 frames and invalidate reordered or changed inventories. `observations.ts` serializes up to eight frames through one private offscreen Cornerstone stack viewport, checks cancellation after awaited boundaries, and emits per-frame failures. It never scrolls visible panes or purges shared caches; disposal destroys only its engine/element. Frame capture uses native acquisition orientation with explicit VOI/inversion and bounded JPEG output (2048 px/1 MiB encoded each). MPR observations use visible-pane capture rather than claiming an acquisition-frame index. Unsupported/incomplete stacks cannot establish full-series review. No new controls are advertised until the task controller is integrated.

- `capabilities.ts` and `reading-tools.ts` expose explicit native reading operations only. Availability follows current pane/data/tool group, while the backend remains authoritative. Navigation/presentation requires observed native state before success, shared native history for presentation undo, same-study scope, finite bounds and guarded awaited boundaries. Stop/takeover must stop task-owned cine. Fusion layers must already belong to the pane. Maintain the toolbar/fixture matrix in `roadmap/ai-backend/CODEX_VIEWER_TOOL_MATRIX.md`.

- `measurements.ts` owns native type-specific annotations, finite canvas/world geometry, bounds/plane checks, native statistics and shared undo, plus scoped segment edits and temporary region tools. Geometry edits clear stale statistics; late/unregistered calculation never becomes a fabricated calibrated value. Imported labels are omitted from model-readable measurements. Exploration geometry must bind to an acknowledged frame/revision; old voice tools retain their context-version policy. Calibration requires a separately reviewed known physical reference. Stop destroys only task-owned lenses/cine. Native segmentation references must match the selected study and representation; contour edits operate an existing unlocked segment, with no mask inference/export. Keep expanded tool coverage and pending fixtures explicit in the matrix.

## Study sharing and native task execution

- `exploration.ts` owns one renderer epoch, claimed-command execution, independent heartbeat, native offscreen observations and Stop/Take over. `exploration-panel.ts` keeps scope, delivery counts, review proposals and collapsed receipts separate from conversation. Never execute saved history.
- The composer Images selector offers None, active viewport, whole reading view, or active series. Default to None; selection is explicit and remains visible between turns. **Send with images** captures fresh pixels on every turn; never require a separate Prepare sharing click or silently send text when requested capture fails. Inventory preparation is internal and bounded. Review remaining frames submits the original request in the same Chat/Research lane with restored acknowledged coverage and preserves any unsent draft. Fresh synthetic/deidentified confirmation is required; Allow viewer tools is separate. Same-study authorized navigation keeps text context; manual reading interaction, settings, account changes or unknown mutation completion stop further actions.
- Keep image delivery and Stop/Take over directly above the composer. Initial turn acceptance and subsequent tool acknowledgments establish delivery; neither establishes diagnostic interpretation. Zero-delivery terminal states must say so. Historical messages show receipts without recreating images. Create preview `<img>` elements only with a real captured source; remove them on release.
- Conversation prose has no nested card chrome; user messages use one restrained surface. Completed native actions live in collapsed Task details, while failures and approvals open it. Voice setup is behind the header Voice button; model identity, Settings and history remain visible. Style all scope/select/button states at 280 px without horizontal overflow.
- Pane observations carry frame/revision identity for geometry; series observations enumerate full frames and retain original index/geometry. Coverage is acknowledged delivery, not diagnostic adequacy. More than one run requires an explicit continuation. Optional Realtime is independent.

- Scope changes revoke the previous lease and clear its visible receipt before enabling Send. Show cumulative distinct series frames sent separately from model status; whole-view sharing has image counts, not a series-completion denominator. Retrying an unconfirmed submission reuses its exact operation identity. Research results appear newest first.
- Scope checks for read-only state/capabilities filter returned series/panes rather than rejecting an adjacent unshared localizer. Pane observations/native commands validate the targeted pane; overview capture validates every visible pane. Known preflight/read failures return a bounded unavailable result; only uncertain mutations revoke control as outcome unknown.
- Takeover tracking compares study/pane/frame/presentation/layout identity, excluding derived measurement statistics and canvas-size changes. Trusted manual reading interactions still take over immediately. Neither background measurement calculations nor sidebar resizing should cancel research.

- Native window presets come from the modality-specific OHIF customization array (matched by preset ID/description), with compatibility for keyed configurations. Resolve them before effects and execute numeric window/level on the named pane. Slice jumps pass the explicit native grid viewport; wait for active-pane selection before commands that use it. Invalid arguments, unavailable controls and unresolved presets are preflight failures, not unknown mutations; genuinely unconfirmed effects still pause the task.
