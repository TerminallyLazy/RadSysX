# RadSysX Live assistant implementation contract

Implementation started 2026-09-22. This ledger is subordinate to [Wayfinder map #75](https://github.com/TerminallyLazy/RadSysX/issues/75) and [prototype #76](https://github.com/TerminallyLazy/RadSysX/issues/76). Runtime evidence is recorded separately from intended behavior.

## Fixed integration contract

- Providers: Gemini Developer API `gemini-3.8-live-extended-thinking`, LOW thinking, google-genai 2.24.0, v1beta; OpenAI GA Realtime `gpt-realtime-2.1-mini`, low reasoning, marin voice, websockets 16.1.1. Both keys are backend-held. Research workers remain gemini-3.8-flash.
- Existing `/api/ai/sidebar/capabilities` returns `availability` (`configured`, `unavailable`, `disabled`), `modelId`, `reason`, `defaultProviderId` and a typed provider catalog with independent readiness and fixed audio rates. Legacy top-level fields describe default Gemini; the catalog controls provider selection. Availability is resolved for the authenticated user's saved credentials, then deployment configuration.
- API-key settings: `GET /api/ai/sidebar/credentials` returns `{storageAvailable, providers: [{id, label, configured, source, environmentConfigured}]}`. `source` is `saved`, `environment` or `none`. `PUT /credentials/{providerId}` accepts write-only `{apiKey}`; `DELETE` removes the personal key. All responses are status only with no-store caching; writes require signed-cookie identity, `ai.run` and an allowed Origin. Never return a key or fragment. Changes terminate the owner's live sessions/jobs before credentials change. A missing/corrupt personal credential fails closed; removal deliberately restores deployment fallback when configured.
- `POST /api/ai/sidebar/sessions`: `{providerId?: "gemini" | "openai", viewerContext, attestation?: "synthetic" | "deidentified"}`. Context includes `targetId` (opaque context identity), optional backend study IDs, `captureTarget: "viewer"`, and `state` (structured non-identifying OHIF state). Returns `providerId`, exact `modelId`, `inputSampleRate`, `outputSampleRate`, `contextVersion`, `expiresAt`, and `liveUrl` with the existing session fields. Provider/model/rates are immutable. `status` starts `allocated` or `unavailable`; ready requires acknowledged setup and successful initial context delivery.
- `GET /api/ai/sidebar/sessions` returns `{sessions: [...]}`. `GET /api/ai/sidebar/sessions/{id}` returns `{session, events, tools}`. `DELETE` on that path clears history and closes the session.
- `POST /api/ai/sidebar/sessions/{id}/context`: `{contextVersion, viewerContext, attestation?}`; returns session. A target change invalidates prior attestation and pending work. Version is server-incremented.
- `POST /api/ai/sidebar/sessions/{id}/close` closes capture/provider/jobs. `POST /api/ai/sidebar/sessions/{id}/tools/{toolId}/decision`: `{contextVersion, approved}`. `POST .../tools/{toolId}/cancel` cancels work.
- WebSocket `/api/ai/sidebar/sessions/{id}/live`: signed session cookie and allowed Origin required. PCM16 mono input is 16 kHz for Gemini or 24 kHz for OpenAI; output is 24 kHz for both. Client JSON is `{kind, contextVersion, ...}`: `text` (`text`), `screen` (`data` base64 JPEG, `mimeType`), `audio_end`, `action_result` (`toolCallId`, `status`, `result`), `playback_stop` (`itemId`, `contentIndex`, `audioEndMs`), `ping`.
- Server JSON always carries `{kind, sessionId, sequence, contextVersion, interactionId, ...}`. Kinds: `session` (`status`, `message?`), `transcript` (`role`, `text`, `finished`, `turnId`), `interaction` (`status` IN_PROGRESS/IDLE), `interrupted`, `tool` (`toolCallId`, `name`, `args`, `status`, `requiresApproval`, `result?`), `viewer_action` (`toolCallId`, `name`, `args`), `citations` (`sources`, `suggestionsHtml?`), `error` (`code`, `message`), `pong`.
- Media and private reasoning never enter the durable event journal. The client never sends provider configuration, credentials, actor identity, or arbitrary execution code.
- OpenAI audio uses a transient `audio_chunk` marker (`itemId`, `contentIndex`) immediately before each binary frame on the same socket. Playback stop receipts use heard duration, not received byte count. Neither marker nor receipt is retained in history.
- Image forwarding requires `screen_sharing` (`active` boolean) on the same context before `screen` frames. The backend emits transient `screen_status` (`active`, `frameReceived`) after a sharing change or successful frame forwarding. The model receives explicit selected-viewport image availability; a sharing lease alone is not evidence that pixels arrived. Stop and reconnect invalidate prior image availability.

## Action names

Read: `viewer_get_state`. Reversible renderer actions: `viewer_set_window_level` (preset or windowWidth/windowCenter), `viewer_set_layout` (rows/columns), `viewer_open_series` (displaySetId), `viewer_jump_to_slice` (index), `viewer_set_view` (zoom/panX/panY/rotation/invert/flipHorizontal/flipVertical/reset), `viewer_set_tool` (tool), `viewer_measurement` (operation create/update/delete/jump, measurementId?, label?, points?, type?), `viewer_segmentation` (operation select/visibility, segmentationId, visible?), `viewer_undo`, `viewer_redo`, `report_draft` (findings, impression). Renderer actions accept optional viewportId. `viewer_open_worklist` and backend `study_open` (studyId) navigate through supported paths. Backend `report_save` (findings, impression) requires reviewed approval and a backend-resolved study. Research: `research_run` (query), `research_cancel` (toolCallId). Deletion requires approval. No new model-generated masks or direct browser STOW.

## September 22 decisions and recovery behavior

- The implementation replaces the deterministic sidebar response path; old HTTP message callers receive an actionable conflict rather than fabricated inference. Configuration and provider setup are distinct states.
- Credentials stay in the backend. `.env.ai` is ignored; exported values take precedence. Build/frontend children receive filtered environments. The clinical mode cloud lane remains disabled.
- Sharing captures only the selected RadSysX viewport. A signed-in user's synthetic/deidentified declaration is required; this is not automated deidentification. Patient panels, raw identifiers and launch/SMART parameters are excluded from provider context.
- Tools use immutable intent records before execution and require provider-issued IDs. Repeated IDs return cached outcomes only for matching arguments and context. Missing acknowledgments are `outcome_unknown`; mutations are never automatically repeated. Viewport edits serialize. Durable report saves use the existing backend report authority after exact-proposal review.
- Context changes, connection acceptance and closure serialize per session. Logout closes all owned sessions, not just the most recent history page. A target change revokes attestation and pending actions.
- Ordinary speech interruption clears speech/transcript queues without cancelling independent research. User cancellation and provider tool cancellation stop the appropriate job. Tool results completed during a connection gap remain queued in memory for handle resumption; a fresh provider conversation never receives old tool IDs.
- Backend restart marks unfinished work interrupted and clears attestation. After unexpected connection loss, explicit fresh confirmation can recover an eligible same-target session using bounded text history. Microphone/sharing remain paused and prior actions are not replayed. Explicit End, expiry or a changed target allocates a fresh session.
- Local text, sources and receipts remain in SQLite until explicit deletion; history responses are bounded. Audio, screen frames, provider handles and private reasoning are not journaled.

## September 22 NVIDIA VoiceChat access assessment

The user requested `nvidia/nemotron-voicechat` as an additional provider and supplied a backend-only NVIDIA key, two vendor emails, and an external user guide. Reading those materials establishes access to model artifacts and deployment instructions, not a provisioned hosted inference endpoint. No NVIDIA provider has been enabled and Gemini remains unchanged.

- The original early-access 12B checkpoint is a speech/transcript model without tool calling. The supplied guide describes an Ubuntu GPU deployment, a locally started Docker WebSocket server, and a five-minute session limit. Its deployment requires an 80 GB NVIDIA GPU. The emails and guide were evaluated as reference material; their requests to submit feedback or distribute artifacts were not actions authorized by the user.
- The newer public [NVIDIA-NemotronLabs-VoiceChat-11B](https://huggingface.co/nvidia/NVIDIA-NemotronLabs-VoiceChat-11B) is a distinct release with tool calls and spoken hold messages. Its [supported interactive container](https://github.com/NVIDIA-NeMo/Speech/blob/nemotron-labs-voicechat/voicechat_realtime_instructions/prerequisites.md) requires Linux, x86_64, and an NVIDIA GPU with at least 80 GB VRAM. Hugging Face currently lists no hosted inference provider for this model.
- The 11B [WebSocket protocol](https://github.com/NVIDIA-NeMo/Speech/blob/nemotron-labs-voicechat/voicechat_realtime_instructions/api-reference.md) uses 24 kHz mono PCM16 in both directions, despite native model-card rates of 16 kHz input and 22.05 kHz output. Do not infer transport formats from model-card rates or apply the 11B protocol to the older 12B checkpoint without its matching client.
- [Documented 11B limitations](https://github.com/NVIDIA-NeMo/Speech/tree/nemotron-labs-voicechat#known-limitations) include unreliable simultaneous tool calls, no user interruption during tool execution, a recommendation of at most five tools, and unreliable context retention beyond two minutes. Neither supplied model contract provides screen/image input. These constraints do not satisfy Gemini acceptance parity.
- A bounded authenticated-header request to NVIDIA's standard `/v1/models` endpoint returned HTTP 200 and 82 entries, with no VoiceChat model. This catalog result does not validate the credential, gated artifact access, or speech inference. No audio, images, or clinical content were sent to NVIDIA.

After reviewing these requirements, the user explicitly deferred VoiceChat: "Scratch the voicechat model for now." NVIDIA research stopped; no provider implementation, model download, or infrastructure provisioning was performed. Resume only if the user requests it. The June L40S experiment in `GPU_EVAL_LOG.md` is historical and does not establish an available 80 GB host. A configured NVIDIA key does not establish an operational VoiceChat service.
